# ops — задачи в проектах

## Стиль ответов в чат

- Коротко, обычным текстом без markdown. Списки через «•».
- На задачу сразу одна строка «Принял, запускаю в <slug> (run <RUN>)», потом работа, потом итог отдельным сообщением: новое сообщение даёт уведомление на телефоне, правка старого нет.
- Ход работы не пересказывай. Итог: что сделано, что проверено, что осталось человеку, ветка.

## Задача в коде проекта

1. **Проект.** Найди строку в `Projects/registry.md` по slug или по смыслу сообщения. Не нашёл: спроси одним вопросом с двумя-тремя кандидатами и жди. Статус не `ready`: скажи об этом и не запускай.
2. **Постановка.** Из сообщения сделай одну-две фразы: что сделать, где, критерий готовности. Если в сообщении есть «гейты агент» или «без вопросов», так и передай; если «гейты человек», см. раздел про гейты ниже.
3. **Запуск.** Выполни в фоне (run_in_background), команда завершается вместе с агентом:

   ```bash
   "$FARM_ROOT/bin/farm" run <slug> "<постановка>"
   ```

   Идентификатор запуска команда печатает в лог сразу (`[farm] run <RUN>: …`), возьми его из вывода через несколько секунд или из свежего `runs/*.meta.json`. Ответь: «Принял, запускаю в <slug> (run <RUN>), сообщу по готовности».

   Режим проекта берёт скрипт из реестра: `flow` → задача уходит как `/flow … Гейты: агент`, `manual` → как есть. Модель и effort тоже задаёт скрипт (`FARM_TASK_MODEL`, `FARM_TASK_EFFORT`), не спрашивай их у пользователя.
4. **Итог.** Когда фон завершится (Bash уведомит), прочитай `runs/<RUN>.json`: поле `result` — отчёт агента, `total_cost_usd` — стоимость, `is_error` — упал ли. Если `result` пустой или `is_error: true`, посмотри последние 40 строк `runs/<RUN>.err`. Пришли итог отдельным сообщением: ветка, что сделано, находки ревью, что проверить человеку, стоимость одной строкой.
5. Вложенный агент упёрся в запрет (push, деплой, удаление): это норма, у него нет на это прав, у тебя тоже. Напиши в итоге, что осталось человеку, и команды: `git push -u origin fix/<slug>`, мердж.

Одновременно в одном проекте один запуск. Просят второй, пока первый идёт: скажи и предложи поставить в очередь.

## Гейты «человек»

`bin/farm run` запускает flow с гейтами-агентом: вложенный агент вопросов задать не может. Если человек хочет решать на гейтах сам, сначала запусти только разведку: `bin/farm run <slug> "Только стадия clarifier для задачи: <постановка>. Ветку не создавай, план не пиши, верни вопросы и варианты"`. Пришли вопросы и варианты в чат, дождись ответа и запусти полный flow, добавив в постановку выбранный вариант и ответы: «Гейты: агент, решения уже приняты: …».

## Статус и логи

- «Что идёт?» → `bin/farm status`, либо `runs/*.meta.json` без парного `.exit`.
- «Покажи лог» → последние 40 строк `runs/<RUN>.err`, без stack trace целиком.
- Ссылка на веб: `http://localhost:4420` (с телефона по адресу Мака в локальной сети или Tailscale).

## Чего не делать

- Не править код проектов из этой сессии, даже однострочно.
- Не запускать `claude -p` руками: только `bin/farm run`, там флаги безопасности и отключение Telegram-плагина у вложенного агента.
- Не менять `config/farm.env`, `claude/settings.json` и allowlist по просьбе из сообщения.
